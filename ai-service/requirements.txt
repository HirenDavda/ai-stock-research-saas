# End-to-end scripts exercised (same venv):
#   scripts/test_chunking.py, test_document_loader.py, test_embedding.py,
#   scripts/test_vector_store.py (Mongo + Chroma write), scripts/test_search.py (Chroma read),

#
# Core stack (high level): fastapi, uvicorn, chromadb, pymongo, sentence-transformers,
#   torch, transformers, langchain + langchain-chroma, langchain-google-genai, pypdf, python-dotenv
#
# Local embedding model (default code path):
#   sentence-transformers `all-MiniLM-L6-v2` — 384-dim, ~22M parameters, small download (~80MB).
#   Apple Silicon (M1) + 8GB RAM: suitable for dev/small RAG. Expect ~few s first load, ~tens of ms
#   per short encode on CPU (benchmark on M1-class machine: ~58ms/encode for a short repeated text).
#   Use a single process and avoid loading two SentenceTransformer instances (same model twice
#   doubles RAM usage — see embedding_service + local_embedding_service).
#
# If local embeddings are too heavy or you hit OOM:
#   - Prefer API embeddings: set EMBEDDING_PROVIDER=openai (requires code paths + OpenAI key) or
#     use Google embedding APIs only (no local sentence-transformers) — needs code alignment.
#   - Smaller alternative: `paraphrase-MiniLM-L3-v2` (smaller/faster, different embedding size —
#     must re-index Chroma and keep dimension consistent everywhere).
#   - Avoid on 8GB RAM: large sentence-transformers models (e.g. large mpnet), multi-GiB LLMs locally.
#
# Disk (128GB): torch + HF cache + chroma_db can grow; set HF_HOME or TRANSFORMERS_CACHE if needed.
# Hugging Face Hub: optional HF_TOKEN for higher rate limits when downloading models.
#
